# V1.0 增强功能使用说明

本完整包的界面与接口版本为V1.0.0，包括六通道UMAP、参考簇解释、预测样本定位、候选对空间与机制比较，以及Optuna TPE优化。各模块共用保存的材料身份、数据划分和研究模型配置。

## 安装

完整安装：
python -m pip install -r requirements-full.txt
python server.py

浏览器访问 http://127.0.0.1:8765。Windows可双击start_windows.bat；macOS/Linux可执行bash start.sh。

如果已经有原始文本向量、且只用本版NPZ权重，可安装requirements.txt、requirements-analysis.txt、requirements-optimization.txt和requirements-llm.txt，不必安装PyTorch/Transformers。HDBSCAN可选，另装requirements-clustering.txt；默认KMeans。

首次UMAP包含Numba JIT编译，可能较慢；页面显示实际阶段，后续复用缓存。没有UMAP依赖时会报错，不以PCA坐标代替UMAP。
软件包不含研究数据、SciBERT权重、论文权重或API密钥。合成演示的输入与结果均有明确标识。

## 1 机制空间与共同分簇参数

在“机制空间 · UMAP”中：
1. 选择合成演示或本地研究模型，以及训练/训练＋验证参考范围。
2. 设置一套UMAP与聚类参数，六通道共用。KMeans设置共同簇数；HDBSCAN的min_cluster_size、min_samples在完整配置JSON中设置。
3. 点击“构建或复用六通道空间”，查看整体与单通道图。
4. 点击参考点查看文本与来源，点击簇标签突出对应簇。
5. 点击“生成六通道簇机制总结”，解释各簇代表记录。

聚类在各通道的归一化高维表示中独立执行，LLM不决定簇成员；不同通道同号簇不是同一物理类别。每簇默认5条代表，以高维簇中心余弦邻近程度选择。未复用摘要的簇通常各调用一次GLM，调用数量随簇数变化。
UMAP二维距离只用于展示，检索与筛选仍使用高维表示。图表可下载PNG（300dpi）、SVG、PDF、CSV与JSON；页面可调点大小、透明度和字号。

整体图需要来自同一固定文本编码器、同一文本模式的原始向量；六套独立PCA坐标不混合。缺原始向量可导入原研究整体坐标；两者均无时显示文件需求，单通道图仍可计算。
合成模式的整体图采用共享合成空间，仅用于展示，非SciBERT或论文结果。

## 2 导入已生成的研究分析文件

工具自动发现原脚本常见产物：
python tools/import_analysis_outputs.py "D:/研究项目/outputs"

显式指定原始向量与整体图：
python tools/import_analysis_outputs.py "D:/研究项目/outputs" --raw-embeddings-dir "D:/原始向量" --global-coordinates "D:/研究项目/outputs/semantic_umap_analysis/umap_coordinates_combined.csv"

也可在可视化完整JSON配置填写：
- channel_directories：键1—6对应单通道分析目录；
- research_output_root：已有研究输出根目录；
- global_coordinates_path：整体六通道坐标CSV；
- raw_embeddings_dir：原始向量目录；
- reuse_existing：是否优先导入已有坐标；
- global_raw_variant：combined或raw，记录原始文本向量模式。

支持channelN_umap_coordinates_and_clusters.csv、umap_training_reference_coordinates.csv、cluster_llm_summary.json及clusters/cluster_llm_summary.json。坐标列支持umap_1/umap_2、umap_x/umap_y。整体文件需含channel_id或channel及完整四元标识。
原始向量支持ch1_raw.csv至ch6_raw.csv的raw_0…列，也可识别单通道目录中的*_scibert_combined.csv和scibert_0…列。所有输入通过四元标识匹配，不按行号猜测。

导入坐标只用于概览，原拟合范围标为导入研究产物。新预测投影始终采用本软件按训练参考拟合的UMAP；仅有二维坐标CSV不能重建真实transform。
簇用当前共同参数重新计算。只有导入cluster_id与当前成员逐条一致，才复用原簇总结；不一致则重新解释。导入摘要标注来源，原始科学依据需核对来源文件。

## 3 单样本预测UMAP

联合预测勾选Top-5，成功后点击“显示所选样本六通道UMAP”；批量预测采用当前“查看样本”。
每通道展示训练参考背景、预测点及Top-5空心标记。UMAP仅拟合训练参考，验证与预测向量通过transform加入。
真实运行保存参考CSV及划分文件SHA256指纹。参考文件改变后，旧运行禁止继续投影，需重新预测，避免旧向量与新参考混用。

## 4 候选对UMAP与机制差异总结

1. 完成候选筛选，点击目标配对表中的一条记录。
2. 点击“显示当前配对UMAP与差异分析”。
3. 六通道在同一参考空间中展示两个预测状态、各自Top-5及材料身份。
4. 点击“生成通道与整体机制差异总结”。

配对解释固定采用训练参考，排除同源文献和自身。首次GLM调用生成六通道共性、差异、分歧和两侧引用，第二次整合整体比较。相同/不同判断必须有两侧支持，缺证据时标记不足。
S1-CH1-R1等引用关联具体样本、来源和描述。检查只验证结构与引用合法性，物理支持关系需人工核对。

筛选D_mech沿用高维距离校准，不由二维图计算。交互候选最多800条，配对表显示前100条，完整结果下载。内置采样未接入热力学相约束和原研究全部输入支持度条件。

## 5 Optuna TPE贝叶斯优化

训练页先准备明确train/val/test，然后编辑搜索配置并启动。
target支持：
- both：机制预训练和冻结动力学均优化；
- pretrain：优化预训练后按固定参数迁移；
- kinetics：需已完成本版NPZ预训练，优化回归头。

默认各10个trial，预训练每trial最多150轮，动力学最多400轮。搜索隐藏层架构、batch size、dropout、学习率和weight decay，可启用中位数剪枝。
TPE先执行少量随机启动试验，再依据已有验证结果选择后续参数；随机启动数为试验预算的三分之一（至少1、至多5）。只设置1个trial时没有后续自适应搜索。
机制目标为0.7×验证通道余弦均值＋0.3×最差通道余弦；动力学目标为验证RMSE。
两集合仍支持固定训练，不能用测试集代替验证集调参。机制优化要求六通道有有效验证机制。
搜索试验不计算测试指标，也不导出带测试真值的试验预测。所有搜索结束后最终训练与测试评估，自动激活模型。
SQLite、trials.csv、best_trial.json保存试验记录。当前未提供暂停或断点恢复；SQLite记录不等于界面支持恢复。

固定训练与本版TPE基于NumPy神经网络；已有PyTorch权重继续兼容推理。本软件不直接执行原论文全部PyTorch优化脚本，重新训练不会自动复现论文指标。数据、划分、PCA、文本模式、架构与随机状态应分别核对。

## 6 GLM配置和结果保存

默认glm-4-plus、temperature=0。复制.env.example为.env，设置ZHIPUAI_API_KEY，或ZHIPU_API_KEY/API_KEY，修改后重启。
只有用户点击生成单样本、簇或配对解释才调用GLM；“检查本地配置”不调用服务、不验证API权限。仅发送所选样本与必要代表证据，不发送权重或整个研究数据集。
没有密钥时显示配置错误，不生成伪造摘要。

新产物：
- outputs/analysis_jobs/任务ID：坐标、图表、簇或配对报告、提示词与任务记录；
- outputs/visualization_cache：本软件生成的训练UMAP缓存，按参考身份、向量、参数和UMAP版本建立指纹；
- outputs/optimized_...：优化study、试验、最佳配置、最终模型；
- outputs/jobs：训练或优化子进程状态与真实日志。

空间分析历史可重新打开完成结果；服务重启后未完成任务标为中断，已保存文件保留。训练旧任务状态未知时先确认进程，不直接并行启动。

## 7 验证与范围

python -m unittest discover -s tests -v
node tests/test_analysis_handoff.cjs

数值测试使用明确标注的合成夹具，实际执行神经网络、UMAP和Optuna。GLM响应替身仅用于接口、引用与导出验证，不是研究机制结果。
真实研究数据、论文权重、SciBERT和有效智谱密钥需由用户在本机配置；包内不含这些文件。验证报告见docs/验证报告.md。
